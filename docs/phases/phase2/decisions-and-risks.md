# 第二阶段决策与遗留风险

## 关键决策

### 原型先完整重命名，再模板化

模板以可运行的 CrossWeb 原型作为唯一源码，避免模板配置掩盖项目引用或资源
路径不一致。重命名完成后先通过构建与运行验收，再建立 `dotnet new` 配置。

### 使用派生大小写名称

`sourceName` 负责 PascalCase 产品名，`casing` 生成器负责全小写和全大写形式。
这使目录、命名空间、npm 包名、消息协议、资源清单和 UI 标签共享同一个用户
输入，避免额外命名参数漂移。

### 模板输出与源仓库状态分离

源仓库的阶段历史和进行中状态不适合作为新项目初始状态。因此模板使用第二个
内容源注入最小 README 与初始 harness，生成项目只保留一个尚未开始的基线验证
任务。

### 模板包显式包含隐藏文件

NuGet 默认排除 `.gitignore`。打包项目启用 `NoDefaultExcludes`，并继续使用明确
的排除清单，确保模板获得必要的忽略规则，同时不把 `.git`、日志和产物带入包。

### 管理员启动策略保持不变

PicoServer 继续监听 `http://+:8090/`。Windows Desktop 清单请求管理员权限，
避免依赖预先配置 URL ACL；界面和 API 返回实际可访问的回环与局域网 URL。

## 遗留风险

- 当前依赖还原会报告多个包源、已知包漏洞与旧框架兼容性警告；依赖升级不在
  本阶段范围内，应在独立任务中评估。
- 代码库仍有既有 XML 注释警告和本机 Visual Studio `LIB` 路径警告，不影响
  当前构建与运行结果。
- 模板保留源解决方案中的项目 GUID。独立生成的解决方案不受影响；若将多个
  生成实例合并到同一解决方案，应重新生成项目 GUID。
- Desktop 运行验收覆盖 Windows；Android、iOS 和 Browser 项目的运行验收仍在
  本阶段范围外。
- 模板包仅在本地生成和验证，尚未发布到公共 NuGet 源。
